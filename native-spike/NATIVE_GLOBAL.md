# Global React Native migration

`App.tsx` hydrates the existing private device storage, then loads `src/app/GlobalNativeApp.tsx`. The same application runs at RNWeb `http://127.0.0.1:4006/` and is the Android entry. The global selector exposes the original Source product/country/design-system/release/scenario axes. It never substitutes a country or design system to make an unavailable selection appear implemented.

Source facts are consumed directly from `src/universal/catalog.ts` and its registries: 16 experiences, 48 release contexts, 15 prepared packs at the initial inventory. The full reproducible inventory is `.codex-temp/native-global/core-source-inventory.json`. Source explicitly declares incomplete coverage of intra-screen states, legacy associations, baseline/scenario variants and native verification. Web implementation does not imply native acceptance.

Italy remains reachable at PI/IT/mobile-first/release-current/active, through its existing native composition. No Italy file is rewritten by Core. Czech Evo is PI/CZ/current/release-future-evo-2027/active and remains labelled **in migration** until its state-level fidelity evidence is accepted. Inactive scenarios and all remaining unported contexts are unavailable in the global selector. No WebView, iframe, browser fallback or portal password is added.

CZ ownership groups export adapters from home/adapter.ts, accounts/adapter.ts, investments/adapter.tsx and profile/adapter.ts. `contracts.ts` is the shared contract. Core integrates each group only after its freeze report, rejects duplicate screen ownership, and filters Search entries whose destination is absent. Source entity IDs travel in route params. The host keeps prior pages mounted and marks them inactive to preserve Back selection/scroll state and invalidate offscreen authorizations; unsupported destinations display a migration notice without discarding the current page. Primary tabs preserve Source order/icons/labels, restore the prior Home occurrence and reserve the physical device bottom inset. The common demo toolbar exposes global Search; the comparison entry hides that toolbar and accepts `screen=search` directly.

Canonical executable decisions live in Source `features`: transaction filters, payment/template/recipient readiness, Home summaries/privacy/fixtures, product detail copy/CTA, curated activity, saving/month reports, sell-order validation, history/pending/bulk selectors, callback and appointment readiness. Legacy Source exports remain. Bank identities, screen types and fund variants are split from UI/asset discovery; analytics chart types are split from DOM renderers. Original custom SVG metadata and the installed Source Lucide geometry are rendered by shared `SourceCustomIcon`, with no rasterization or original asset modification. Existing shared control defaults remain available to Italy; current/Evo/mailbox geometry is selected explicitly.

Porting order after CZ: PI RO baseline; CZ baseline/coapping/robo releases separately; SK; HU; RS baseline/Future Gain; BA/BA_BL; SI; Kids SK/HU/RO. Release-preview contexts and prepared SME/other-market packs require their own genuine implementations and verification; they stay unavailable meanwhile.

Run native strict typecheck, lint with max-warnings0, Jest and RNWeb build after all ownership groups freeze. Core also runs Source `npm run verify`. Compare Source and RNWeb at matching viewport, counts, language, state and data; report actual differences in group fidelity ledgers. Native OS/keyboard/biometric/font/SVG behavior needs installed acceptance in addition to RNWeb evidence. A global APK candidate belongs under `.codex-temp/native-global/apk/` with a distinct filename and checksum; do not replace public Italy artifacts, upload Drive or activate OTA from this task.
