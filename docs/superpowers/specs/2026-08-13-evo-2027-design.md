# Evo 2027 Future Preview Design

## Goal

Add a Czech-only `Evo 2027` future preview under `PI → Czech Republic → current design system`, initially rendering the same visible Home and CZ Robo content as `App 2027`, while keeping its release and feature identity independent for later changes.

## Scope

- Add `release-future-evo-2027` with the stakeholder label `Evo 2027`.
- Expose it only when the selected context is `PI`, `CZ`, and `current` design system.
- Keep the existing Future selector order and append `Evo 2027` after `App 2027`.
- Give Evo its own `fx_evo2027Homepage` feature metadata, manifest, UI-map entry, and feature flag.
- Reuse the current App 2027 Home composition for the first Evo version; the independent feature gate is the extension point for future Evo-only UI changes.
- Preserve CZ Robo Investments behavior in Evo because the current App 2027 bundle inherits that feature.
- Do not change Baseline, CZ Chatbot, CZ Robo, or App 2027 behavior.

## Architecture

The release registry owns the new release identity and includes both the existing CZ Robo feature and the new Evo Homepage feature. The feature resolver activates the Evo Homepage only for the Evo release, PI, CZ, current design system, and active scenario. Home routing treats the Evo flag as an App 2027-compatible Home presentation, while the product data and account-detail special handling include the new release so the visible CZ App 2027 content remains coherent.

The release selector filters the new bundle through the existing feature metadata rules and adds the new release to the future order. Because the Evo feature is country-scoped to CZ, it naturally remains hidden for every other country; the project-pack release list is also country-aware so registry evidence does not claim Evo coverage outside CZ.

## Data and behavior

- Evo release ID: `release-future-evo-2027`.
- Evo Homepage feature ID: `fx_evo2027Homepage`.
- Feature scope: `countries`, countries `['CZ']`, product `PI`, design system `current`.
- Release bundle features: `['fx_czRoboAdvisor', 'fx_evo2027Homepage']`.
- Evo Home initially reuses `App2027HomeScreen` for the shared Home composition, quick actions, contextual rail, product groups, activity, portfolio, appearance studio, and navigation. Its `Accounts` group is the deliberate Evo divergence: it reuses the CZ Robo evolution `ProductCard` model and account quick actions for current accounts, while retaining the responsive CZK/EUR/USD currency badges in place of the generic account icon. Other Evo product groups remain on the App 2027 composition.
- Deep links using `release-future-evo-2027` remain valid through the existing `ReleaseId` and URL-sync paths.

## Error and compatibility handling

The existing selector normalization falls back to Baseline if a release is not compatible with the selected product, country, or design system. No new fallback path is needed. If the scenario is inactive, the existing resolver disables both App 2027 and Evo Home features and the existing inactive screen remains authoritative.

## Verification

- Registry contract tests assert the release, feature, manifest, UI map, and CZ-only metadata.
- Demo top-bar tests assert Evo is visible for CZ and absent for non-CZ countries.
- Home routing tests assert an Evo deep link renders the App 2027 Home composition and retains the CZ Robo entry.
- Focused tests and TypeScript/build checks are run after implementation; existing unrelated workspace diagnostics remain explicitly reported if present.

## Limitations

Evo is an independent release/feature identity, but its initial visible composition reuses the existing App 2027 Home component and shared App 2027 child components. Future Evo-only changes should be introduced behind `fx_evo2027Homepage` or in a dedicated Evo composition once the desired divergence is specified.
