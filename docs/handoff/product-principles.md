# Product Principles

Last updated: 2026-05-27

## 1. Demo First, But Honest

The platform is stakeholder-facing. It should feel interactive and convincing, but must not claim coverage that does not exist.

## 2. Same Shell, Explicit Differences

PI and SME should share the shell and design foundations where possible. Differences must be explicit in product, country, release, feature, and screen registries.

## 3. Baseline Is Official

Baseline means stable/UAT-approved state. A release feature becomes baseline only when explicitly promoted.

## 4. Release Is Evolution

Release work can be previewed and toggled, but must remain distinguishable from baseline.

## 5. Country Differences Are First-Class

Country-specific copy, capability, currency, legal copy, and feature availability should be modeled in config or registries, not hidden inside components.

## 6. AI Needs A Map

Screens, components, flows, features, screenshots, and similarities should be indexed so AI can assemble new flows from known project material instead of inventing unsupported UI.

## 7. Integration Is A Product Requirement

The standalone demo should remain extractable into a larger host platform. Avoid coupling core project meaning to the current Vite app shell.
